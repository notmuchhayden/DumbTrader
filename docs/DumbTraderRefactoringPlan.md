# DumbTrader 구조 점검 및 리팩토링 계획

## 점검 범위와 이번 수정

앱 시작과 DI, Xing COM 수신·조회·주문, SQLite 저장, 국내주식·해외선물 모니터링, Roslyn 전략 실행, 페이퍼·시뮬레이션, 계좌 요약 및 테스트의 연결을 점검했다.

- 국내주식 시뮬레이션이 동일 종목의 실시간 스크립트 상태를 초기화하고 공유하던 문제를 수정했다. 실시간은 종목별 상태, 시뮬레이션은 실행별 상태를 갖는다. 시뮬레이션은 시작 시 스크립트 경로를 복사하고 매 봉 실제 모의 보유 수량을 `HasPosition`에 반영한다.
- 신규·정정·취소 주문 응답을 매핑할 때 증권사가 되돌려 준 입력 비밀번호를 결과 객체에 복사하던 부분을 제거했다. 요청에 필요한 비밀번호 전달은 기존 API를 사용한다.

## 우선순위

| 우선순위 | 관찰한 코드와 영향 | 변경 방향 및 완료 기준 |
| --- | --- | --- |
| 1 | `StockDashboardViewModel`의 틱 콜백이 `StrategyService`의 동기 결과를 기다린다. 전략 지연이 UI 조작과 시세 반영에 전파될 수 있다. | 시세 콜백에서 정규화한 틱을 전달하고, 전략은 종목별 순차 작업에서 실행한다. 체결 원본을 쓰는 분봉 집계와 최신값만 표시하는 UI 갱신은 수신 직후 분기한다. 대량 재생 중 UI 수신 지연과 전략 지연을 각각 기록하고, 종료 시 대기 작업을 정리한다. |
| 2 | `App.xaml.cs`에는 장수명 DbContext와 팩터리 사용 서비스가 섞여 있다. 계좌·주식 데이터 서비스는 공유 컨텍스트를 사용하고, 일부 차트·전략 경로는 작업별 컨텍스트를 쓴다. | 주식 시세 저장, 종목 조회, 계좌 설정 순으로 작업별 DbContext로 전환한다. 화면에는 필요한 데이터만 반환하고 DB 객체를 넘기지 않는다. 동시 조회·저장, SQLite 잠금 후 재시도, 기존 파일의 데이터 보존을 검증한다. |
| 3 | `StockDashboardViewModel`과 `OFutureDashboardViewModel`에 구독, 분봉 보정, DB 저장, 전략 실행과 ScottPlot 그리기가 함께 들어 있다. | 수신 세션·저장 보정을 서비스로 이동하고, ViewModel은 선택 상태와 스냅샷 바인딩을 맡는다. 봉 키에서 X좌표로 변환하는 순수 계산과 WPF 렌더링을 분리한다. 기존 SC·OVC·주식 틱 재생 결과와 마커 위치가 같아야 한다. |
| 4 | `StockDataService`, `OFutureDataService`, 계좌와 주문 서비스가 COM 이벤트 등록, 타임아웃, 실패 및 쿼리 교체를 각자 다룬다. `XingTrQuerySchedulerService`는 이미 요청 큐를 공용으로 제공한다. | TR별 입력·파서는 유지하고, 소유 Dispatcher에서 요청과 응답을 연결하는 공통 전송 계층을 만든다. 늦은 응답, 연결 해제, 쿼리 교체, 동시 요청에서 결과가 다른 종목·계좌로 연결되지 않아야 한다. 실제 Xing 모의 환경에서 TR별 입력·응답을 대조한다. |
| 5 | `SummaryViewModel`, `LogViewModel` 같은 transient ViewModel이 장수명 서비스 이벤트를 구독하고, 여러 화면이 비슷한 생명주기 관리를 반복한다. | 앱 전체에서 한 인스턴스가 필요한 구독과 화면 단위 구독을 구분한다. 화면 단위 구독은 닫힐 때 해제한다. 창과 탭을 반복 생성해도 조회·로그 이벤트 처리 횟수나 DispatcherTimer 수가 늘지 않아야 한다. |
| 6 | `DumbTraderDbContext.EnsureCreatedAndExtended`에 테이블 보충 SQL이 누적된다. `tests/StrategyEvolution`의 콘솔 테스트는 전략, 렌더링, 원장, 저장을 한 번에 실행한다. | 기존 SQLite 파일을 버전 있는 스키마 갱신으로 넘기고 초기 설치, 구버전 업그레이드, 마이그레이션 재실행을 각각 검증한다. 테스트는 순수 전략·시간 계산, SQLite 통합, WPF 렌더링, Xing 연동으로 실행 경계를 나눈다. |

## 주문 경로 개선

국내주식 주문 원장은 초기 단계이며, 전략 신호의 자동 주문 전송은 별도 작업이다. 실주문 개발은 [국내주식 실주문 개발 계획](StockLiveTradingPlan.md)을 기준으로 진행한다. 구조 개선 중에는 증권사 주문 이벤트를 계좌 요약과 원장이 각각 소비할 수 있도록 하고, 스크립트 상태·페이퍼 보유·증권사 확인 보유를 분리한다.

## 적용 순서

1. 현재 빌드 및 저장 데이터 재생을 기준선으로 확보한다. 로그인·재연결, 분봉 보정, 시뮬레이션과 실시간 동시 실행은 각각 독립적으로 재현한다.
2. 국내주식부터 틱 평가를 UI에서 분리하고, 같은 재생 입력으로 이전과 이후 신호 수·순서·지연을 비교한다. 완료 후 해외선물 경로에 같은 경계를 적용한다.
3. 작업별 DB 컨텍스트와 버전 있는 마이그레이션을 순차 반영한다. 기존 DB 사본에서 분봉·전략·주문 원장의 행 수와 주요 키를 비교한다.
4. TR 전송 계층과 화면 구독 생명주기를 정리한다. COM 리소스가 없는 환경의 자동 테스트와 Xing 모의 환경 검증을 별도로 기록한다.

## 적용 기록

- 국내주식의 기본 전략은 종목별 순차 작업에서 실행한다. 전체 동시 실행을 두 건으로 제한한다. 종목별 대기열이 256건에 도달하면 새 평가 요청을 건너뛰고 로그에 남긴다. 분봉 집계는 평가 대기열을 통과하지 않으며, 기준가 표시는 화면 갱신 주기에 합친다.
- 국내주식 실시간 COM 콜백에서 초 단위 틱의 공유 DbContext 조회·추적을 제거했다. 차트는 기존 일봉과 분봉 저장 경로를 사용한다. 대시보드 일봉 조회에는 작업별 컨텍스트를 사용하고 선택 변경 이후 도착한 이전 응답은 버린다.
- Summary와 로그 ViewModel은 앱 단위 인스턴스를 사용한다. 수신 정지 및 종료 시 대기 중인 국내주식 전략 작업을 비운다.
- 해외선물 워커 전환, 나머지 공유 DbContext 제거, 대시보드 서비스 분리, 공통 COM 전송 및 스키마 버전 관리는 후속 단계다.
