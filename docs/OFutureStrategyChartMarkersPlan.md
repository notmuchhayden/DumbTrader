# 해외선물 전략 신호·체결 차트 표시 개발 계획

- 작성일 2026-11-18
- 상태 개발 계획
- 관련 문서 [해외선물 대시보드 개발 계획](OFutureDashboardDevelopmentPlan.md) · [OVC 기반 분봉 갱신 계획](OFutureRealtimeMinuteBarsPlan.md)

## 1. 화면에서 확인할 수 있는 것

해외선물 캔들 위에 전략이 판단한 시점과 체결이 기록된 시점을 표시한다. 상세 화면의 시뮬레이션에는 결과 전용 캔들 차트를 추가하고, 실시간 대시보드에는 기존 일봉·10분봉·1분봉 위에 마커를 겹쳐 그린다.

| 마커 | 의미 | 위치 |
| --- | --- | --- |
| 빈 위쪽·아래쪽 삼각형 | 매수·매도 신호 | 전략이 평가한 봉과 판단 기준 가격 |
| 채운 원 | 체결로 포지션 진입 | 체결을 기록한 봉과 체결 가격 |
| 채운 마름모 | 체결로 포지션 청산 | 체결을 기록한 봉과 체결 가격 |

범례에 신호와 체결의 모양을 표시하고, 방향은 색과 도형 또는 텍스트를 함께 사용한다. 마커에 마우스를 올리거나 클릭하면 전략명, 계약, 이벤트 시각, 기준가 또는 체결가, 방향과 수량을 보여준다. 체결은 툴팁에 모의·페이퍼·실계좌 출처를 표시한다. 신호의 수량과 체결 수량은 각각 표시한다. 실시간 전략의 신호에는 주문 미전송 상태를 표시한다. HOLD와 오류는 기존 상태 줄에서 확인한다.

예를 들어 10:10 봉의 종가에서 BUY가 나오고 다음 봉의 시가에 모의 체결되면, 10:10 봉에는 빈 삼각형이, 다음 봉에는 채운 원이 표시된다. 다음 봉이 없거나 체결 조건을 충족하지 못하면 신호만 표시하고 상세 정보에 상태를 남긴다.

## 2. 기존 코드와 연결할 지점

| 경로 | 현재 동작 | 계획 |
| --- | --- | --- |
| `OFutureSimulationService` → `OFutureStrategyViewModel` → `OFutureDetailView.xaml` | 저장된 봉으로 전략을 실행하고 집계 결과를 표시한다. 종가 신호는 다음 봉 시가에 장부가 처리한다. | 실행에 사용한 봉과 신호·모의 체결 이력을 반환하고, 요약 아래 결과 차트에 표시한다. |
| `OFutureStrategyService.StrategySignalUpdated` → `OFutureDashboardViewModel` | 선택 계약의 수동 전략 결과를 상태 줄에 표시한다. 이벤트는 수신 UTC와 선택 세대를 포함한다. | 판단 가격과 거래소 거래일·현지 체결 시각을 이벤트에 추가한다. 대시보드의 선택 세대 검사를 마커에도 적용한다. |
| `PaperTradingService.ActiveSignal` → `StrategyEvolutionRuntime` | 활성 버전의 페이퍼 경로에서 신호를 게시하고 런타임이 최신 상태를 보관한다. | 활성 버전의 신호를 원본 이벤트에서 한 번 기록한다. 페이퍼 체결을 표시할 때는 장부의 실제 상태 변경으로부터 별도 이벤트를 만든다. |
| `UpdateMinutePlot` 및 대시보드 일봉 렌더링 | ScottPlot에 캔들을 다시 그린다. 분봉은 거래 공백을 접은 연속 슬롯, 일봉은 날짜 축을 사용한다. | 동일한 캔들 배열로 봉 키와 X 좌표의 대응표를 만들고, 캔들 다음에 마커를 그린다. |

## 3. 이벤트와 차트 좌표

- 공통 이벤트 모델에는 이벤트 ID, 출처, 계약 코드, 실행 ID 또는 실시간 세션 ID, 전략 파일명 또는 버전 ID, 종류(신호·진입·청산), 매수·매도 방향, 가격, 수량, 판단에 사용한 봉 주기 또는 틱 여부를 담는다. 체결에는 대응 신호 ID와 체결 전후 포지션을 함께 남긴다.
- 거래소 거래일과 시각은 봉 배치에 사용하고, 수신 UTC는 지연을 확인하는 데 쓴다. 시뮬레이션 일봉 신호는 종가 판단으로 표기한다. 일봉의 저장값 `000000`을 정확한 판단 시각으로 표시하지 않는다.
- 일봉 키는 해당 계약의 거래일을 사용한다. 실시간 분봉은 OVC 집계와 같은 해외 거래일·현지 시각에서 1분 키를 만들고, 10분 키는 대시보드 집계 규칙을 재사용한다. 같은 실시간 이벤트를 세 차트에서 각 주기의 봉 위에 투영한다.
- 분봉 마커의 X 좌표는 현재 화면에 그리는 정렬된 봉의 슬롯에서 가져온다. 기간 필터, 서버 보정, 늦게 도착한 봉으로 슬롯이 바뀌면 좌표를 다시 계산한다. 봉을 아직 찾을 수 없으면 이벤트를 보관해 다음 갱신 때 다시 매칭한다. 거래 공백의 이벤트를 인접 봉으로 옮기면 시점이 왜곡되므로 정확히 매칭된 봉에만 그린다.
- 이벤트의 Y 좌표는 판단 가격 또는 체결 가격이다. 동일 봉·가격에 여러 이벤트가 겹치면 화면에서 하나의 묶음과 건수를 표시하고 클릭하면 시간순 상세 목록을 연다. 실제 가격은 그대로 유지한다. 자동 Y축 범위는 표시 중인 캔들과 마커를 함께 고려한다.

## 4. 구현 순서

### 4.1 시뮬레이션

1. `OFutureSimulationRunResult`에 이번 실행의 캔들 스냅샷과 이벤트 목록을 추가한다. 결과 화면은 그 스냅샷을 사용해 실행 후 DB가 갱신돼도 동일한 캔들을 보여준다.
2. `OFutureSimulationService`에서 거래 시작일 이후의 BUY·SELL을 종가 신호로 기록한다. 워밍업 봉은 지표 계산에 포함하고, 거래 이력에는 실행 구간의 판단만 남긴다. 다음 봉으로 넘기는 정보에 신호 ID를 포함한다.
3. `StrategyLedger.Fill` 호출 전후 포지션을 비교하거나 장부에서 처리 결과를 반환해 실제 모의 진입·청산만 추가한다. 증거금 부족, 동일 방향 포지션, 마지막 봉처럼 체결이 생기지 않는 경우는 신호 상세에서 확인할 수 있게 한다. 체결 가격은 장부의 시가 기준 가격으로 표시하고 수수료와 슬리피지 비용은 상세 정보에 표시한다.
4. `OFutureStrategyViewModel`에서 완료된 실행의 결과 요약과 차트를 함께 반영한다. 계약·전략·주기가 바뀌거나 실행이 취소되면 오래된 실행의 완료 콜백이 현재 차트를 덮어쓰지 않도록 실행 ID를 확인한다.

### 4.2 실시간 대시보드

1. 수동 전략 결과 발행 시 `OFutureRealData`의 판단 가격과 거래소 시각을 함께 전달한다. 활성 버전은 대시보드가 OVC마다 조회하는 최신 상태 텍스트 대신, `ActiveSignal`의 실제 게시 건을 기록한다. 활성 전략의 판단 시각은 신호를 생성한 원본 봉 또는 틱에서 전달한다.
2. 계약·전략 버전·수신 세션별 이벤트 목록을 메모리에 보관한다. 같은 세션에서 계약을 다시 선택하면 해당 계약의 기존 이벤트를 복원한다. 늦게 완료된 수동 판단은 실행 당시의 선택 세대와 수신 세대를 확인한 뒤 반영한다. 초기 구현의 이력은 앱 세션 동안만 유지하며 메모리 한도를 둔다.
3. 실시간 시세 콜백에서는 이벤트를 큐에 추가한다. 기존 차트 갱신 주기에 큐를 소비하고, UI Dispatcher에서 캔들과 마커를 한 번 갱신한다. 중복 전달은 이벤트 ID로 제거한다. 같은 초의 다른 신호는 각각 보관한다. 확대·이동 상태를 보존하고 화면 표시 범위에 해당하는 마커를 그린다.
4. 현재 수동 실시간 경로는 신호 전용이다. 활성 버전의 페이퍼 체결은 장부가 포지션 변경을 확정했을 때 표시한다. 실계좌 체결 표시가 추가되면 브로커의 체결 확인 이벤트와 주문·체결 ID를 사용한다. OVC 시장 체결, BUY·SELL 신호, 주문 접수 응답만으로 계좌 체결 마커를 만들지 않는다.

### 4.3 일봉·10분봉 전략을 실시간에서 보여 주는 조건

현재 DB에서 만든 계약별 스크립트는 `IsSimulation` 및 시뮬레이션 주기를 검사한다. 실시간 마커가 먼저 구현되면 기존 실시간 대응 전략의 결과부터 표시할 수 있다. 생성한 일봉·10분봉 전략까지 실시간으로 보려면 아래 실행 경로가 필요하다.

1. 전략별 평가 주기와 완성 봉 여부를 실행 입력으로 전달한다. 시뮬레이션과 실시간 평가에서 동일한 전략 계산을 쓸 수 있게 하고 주문 정책은 실행 경로에서 관리한다.
2. 10분봉은 OVC 기반 집계의 완성 봉, 일봉은 거래 세션이 마감돼 확정된 일봉을 평가한다. 이전 완성 봉으로 초기 상태를 채우고 새로 마감된 봉당 한 번만 평가한다. 거래일·세션 마감과 데이터 확정 여부는 거래소와 현재 저장 경로에 맞춰 확인한다.
3. 진입·청산 판단에 필요한 포지션은 해당 전략의 시뮬레이션 또는 페이퍼 장부에서 가져온다. 실시간 전략 시작·변경·재연결 시 워밍업과 재평가 범위를 정의한다. 세션 내 같은 봉을 다시 받아도 이미 발행된 신호나 모의 체결을 중복 생성하지 않는다.

## 5. 검증 및 완료 기준

| 검증 | 기대 결과 |
| --- | --- |
| 일봉·1분봉·10분봉 시뮬레이션에서 진입과 청산 재생 | 신호는 판단 봉, 체결은 다음 봉 시가에 나타난다. 체결 마커 수가 결과의 진입·청산 횟수와 일치한다. |
| 마지막 봉 신호, 증거금 부족, 워밍업, 미청산 포지션 | 마지막 봉과 증거금 부족에는 신호만 표시한다. 워밍업과 미청산 포지션으로 가짜 체결을 만들지 않는다. |
| 일봉·분봉 기간 전환, 거래 공백, 야간 세션, 자정, 서버 보정 | 마커가 대상 캔들에 붙고, 봉 배열이 바뀌어도 정확한 위치를 유지한다. |
| 계약 전환, 전략 버전 변경, 수신 정지·재시작, 시뮬레이션 취소 | 오래된 이벤트가 현재 화면에 섞이지 않는다. 같은 세션에서 계약을 재선택하면 해당 계약의 마커를 볼 수 있다. |
| 수동 실시간 신호와 활성 버전 페이퍼 재생 | 전략별 신호가 중복 없이 표시된다. 페이퍼 체결을 실계좌 체결로 표시하지 않는다. |
| 한 봉에 신호 집중, 같은 초에 여러 이벤트, OVC 대량 재생 | 개별 이벤트가 상세 목록에 남고, 화면 갱신이 묶여 처리된다. 교차 스레드 예외가 없고 줌·이동과 차트 응답성이 유지된다. |
| 생성된 일봉·10분봉 전략의 실시간 평가 | 완성 봉에서만 평가하며, 동일한 봉과 포지션을 입력하면 시뮬레이션·페이퍼 경로에서 같은 신호를 낸다. |

봉 키 매핑, 이벤트 중복 제거, 장부 상태와 체결 마커의 일치는 자동 검증으로 확인한다. ScottPlot 마커 위치, 범례, 툴팁과 대량 갱신은 저장 데이터 재생으로 화면에서 확인한다.

## 6. 구현 검증 기록

- Visual Studio MSBuild와 x86 전략 테스트를 통과했다. 일봉·1분봉·10분봉 재생, 자정 경계, 마지막 봉 미체결, 증거금 부족, 미청산 포지션 및 활성 버전 페이퍼 신호와 장부 체결 연결을 검증했다.
- 실행 폴더 SQLite를 읽기 전용으로 열어 계약 12개의 전략을 하나의 x86 프로세스에서 재생했다. 신호는 판단 봉 종가, 체결은 다음 봉 시가에 배치됐고 진입·청산 마커 수는 장부 집계와 일치했다.
- 동일 초 이벤트 4,000건으로 중복 제거, 계약별 조회, 수신 재시작 후 이전 이벤트 차단을 검증했다. 동일 좌표 묶음과 캔들 500개·마커 2,000개의 ScottPlot 렌더링도 검증했다.
- Xing 실제 피드에서 거래일 전환 후 일봉 확정 저장 시점과 대량 수신 중 차트 상호작용은 현장 검증이 남아 있다. 현재 환경에는 실행 중인 DumbTrader 창이 없으며 Windows 화면 도구가 네이티브 파이프에 연결되지 않는다.
