# 해외선물 OVC 기반 분봉 갱신 계획

작성일: 2026-11-17  
상태: 코드 구현 완료, 실시간 Xing 모의계정 검증 대기  
관련 문서: [해외선물 대시보드 개발 계획](OFutureDashboardDevelopmentPlan.md)

## 1. 목표

관심계약 전 종목의 OVC 실시간 체결을 받아 메모리에 최근 체결 흐름을 유지하고, 이를 이용해 1분봉을 실시간으로 만들고 갱신한다. `o3103` 호출은 관심계약별 10분 주기 서버 보정에 사용해 호출량을 줄인다. 10분봉은 저장된 1분봉을 집계해 표시하며, 일반적인 분봉 갱신을 위해 `o3103`의 10분 주기 조회는 하지 않는다.

화면 진입 때마다 과거 분봉을 다시 조회하던 동작을 없앤다. 화면은 DB에 저장된 봉을 즉시 읽고, 실시간으로 만들어진 봉과 정기 서버 보정 결과를 이어 붙인다.

## 2. 현재 상태 및 핵심 변경 지점

- `OFutureRealDataService`는 OVC 이벤트에서 체결가, 체결시각, 체결수량, 누적수량 등을 읽어 이벤트를 발생시킨다.
- 대시보드는 OVC 최신값을 종목별로 모아 주기적으로 `OFutureLatestTradeSnapshots`에 저장한다. 이 저장 경로는 같은 주기 사이의 이벤트를 최신값 하나로 합치므로 체결 원본을 이용한 봉 집계에 재사용할 수 없다.
- `OFutureMinuteBars`에는 `(Symbol, IntervalMinutes, TradeDate, TradeTime)` 키로 1분봉과 10분봉을 저장할 수 있다.
- 차트가 로드될 때 대시보드는 `o3103` 1분봉을 요청하고, 응답 페이지 처리가 끝나면 10분봉도 요청한다. 이 요청 흐름을 화면 로드와 분리해 정기 보정으로 옮긴다.
- 모든 관심계약 종목에 대한 OVC 구독은 `OFutureDashboardViewModel.SyncOFutureSubscriptions()`에서 관리한다. 카드 선택에 따라 구독을 교체하지 않는다.
- 주식 및 해외선물의 요청형 TR은 앱 공통 스케줄러를 공유하며 최근 600초 합계 200회, 최소 전송 간격 1.1초 제한을 적용한다. OVC 실시간 이벤트는 이 TR 예산과 별도다.

## 3. 처리 흐름

```text
OVC 체결 이벤트
  ├─ 원본 이벤트를 종목별 10분 롤링 버퍼에 추가
  ├─ 이벤트 시각 기준 1분봉을 계산/갱신
  ├─ 분봉을 메모리 캐시에 반영하고 DB upsert 큐에 전달
  └─ 기존 최신 체결 스냅샷 및 화면 표시 갱신

앱 시작/화면 활성화
  ├─ DB에서 저장된 분봉 로드
  ├─ 관심계약 전체 OVC 구독
  └─ 10분 주기 서버 보정 작업 시작
       └─ 관심계약별 o3103 1분봉 조회 → DB upsert → 해당 분봉 갱신

10분봉
  └─ 완성/갱신된 1분봉을 거래 세션 기준으로 묶어 로컬 생성
```

원본 이벤트의 집계는 대시보드의 최신 스냅샷 coalesce 이전에 수행해야 한다. 구현 위치는 `OFutureRealDataService`의 OVC 수신 경로 또는 OVC 이벤트를 직접 구독하는 별도 `OFutureMinuteBarAggregator` 서비스로 한다. 대시보드의 `_pendingTrades`는 최신 상태 저장용으로 남기고 원본 체결 집계에 사용하지 않는다.

## 4. 분봉 집계 규칙

### 4.1 1분봉

- 봉 키는 종목, 해외 거래일자, 분 버킷으로 한다. DB 기존 키를 유지하기 위해 `TradeDate=yyyyMMdd`, `TradeTime=HHmmss` 형식에서 분 시작 시각(`HHmm00`)을 사용한다.
- 이벤트 버킷은 OVC가 제공하는 해외 거래일자와 현지 체결시각으로 정한다. PC 수신시각으로 봉을 나누지 않는다.
- 시가는 분 내 첫 체결가, 고가/저가는 최고/최저 체결가, 종가는 가장 늦은 체결의 가격으로 계산한다.
- 거래량은 분 내 각 OVC 체결의 `TradeQuantity` 합계로 계산한다. `TotalQuantity`는 누적값이므로 합산하지 않는다.
- 같은 초에 여러 체결이 올 수 있으므로 시각만으로 원본 이벤트를 중복 제거하지 않는다. 도착 순서와 거래소 시각을 함께 보존하고, 시간 역전/지연 도착 시 기존 분봉을 다시 계산한다.
- 열린 현재 분봉은 체결이 들어올 때마다 메모리와 그래프를 갱신한다. 분 경계에서 완성 처리하고 DB에 upsert한다. 앱 종료 때 열린 봉도 flush한다.
- 최대 보관 길이는 종목별 최근 10분의 원본 이벤트다. 이벤트가 없는 분은 인위적으로 0 거래량 봉을 만들지 않는다.

### 4.2 10분봉

- 서버에 10분봉을 추가 요청하지 않고 1분봉을 로컬에서 묶는다.
- 10분 경계는 현지 거래소의 거래일 및 세션 기준으로 정한다. 세션 시작이 정각 10분 배수와 다르면 거래 세션 기준의 구간 규칙을 적용한다.
- 시가/고가/저가/종가는 포함된 1분봉을 시간순으로 집계하고 거래량은 1분봉 거래량 합으로 계산한다.
- 세션 경계·서머타임·휴장일 처리는 거래소 규칙이 확인되기 전까지 설정 가능한 경계 함수에 격리하고, 임의의 한국 시간 변환을 하지 않는다.

## 5. `o3103` 주기 보정

- 차트 선택이나 기간 변경은 `o3103` 요청을 만들지 않는다. 최초 표시는 DB 데이터로 한다.
- 보정 작업은 앱의 Xing 세션이 연결되고 해외선물 모니터의 수신이 활성화된 동안 10분마다 관심계약 목록을 스냅샷해 실행한다.
- 각 계약에 대해 `ncnt=1`인 `o3103`만 요청한다. `readcnt`와 연속 페이지 수는 필요한 최신 구간을 덮을 만큼으로 제한하며, 서버 응답의 원본 OHLCV를 DB에 upsert한다.
- 일반 TR 호출은 전부 공통 스케줄러를 통과한다. 스케줄러가 다른 주식/계좌/주문 TR 때문에 지연시키면 대기하고, 주기 작업이 쌓이지 않게 같은 종목의 중복 보정 작업을 병합한다.
- 종목 수가 200에 가까우면 이 작업만으로 공유 10분 예산을 모두 소진할 수 있다. 종목 수와 최근 TR 사용량으로 회차별 작업 가능량을 계산하고, 과도한 대기열이 생기면 보정 지연/누락을 상태와 로그에 표시한다. 서버 보정이 10분 경계를 넘겨도 요청을 급히 몰아 보내지 않는다.
- 종목 추가/삭제, 모니터 정지, Xing 연결 해제, 화면/앱 종료 시 아직 전송하지 않은 작업은 취소한다. 이미 전송한 요청은 응답 컨텍스트를 유지해 정상적으로 완료/실패 처리한다.
- 조회가 실패하면 OVC 합성 봉과 기존 DB를 유지하고 다음 주기에서 재시도한다. 실패 응답으로 최근 봉을 지우거나 덮어쓰지 않는다.

## 6. DB 및 메모리 보관

- 최근 10분 원본 OVC 이벤트는 메모리에만 보관한다. 저장량을 제한하고 오래된 이벤트를 순환 제거한다.
- 1분봉/10분봉은 기존 `OFutureMinuteBars` 테이블에 upsert한다. 별도 원시 틱 테이블은 만들지 않는다.
- `OFutureLatestTradeSnapshots`는 화면 재진입용 종목별 최신 체결 스냅샷으로 유지한다. 이것을 체결 이력이나 봉 원천으로 취급하지 않는다.
- DB 기록은 비동기 직렬 큐로 수행한다. 메모리 집계가 DB I/O를 기다리며 OVC 콜백을 막지 않게 한다.
- 서버 보정 봉이 로컬 합성 봉과 겹치면 `ReceivedAtUtc`가 최신인 서버 결과가 이기도록 한다. 다음 OVC 체결이 같은 열린 분에 오면 해당 분봉을 다시 갱신한다.
- 원시 이벤트를 영속화하지 않으므로 앱 종료/강제 종료 중의 미완성 틱 이력은 복원되지 않는다. 마지막 분봉은 종료 시 flush하고, 앱 재시작 뒤 서버 보정이 과거 데이터를 정정한다.

## 7. 화면/상태 표시

- DB 로드, OVC 합성 중, 서버 보정 대기, 서버 보정 중, 보정 완료, 보정 지연/실패를 구분해 표시한다.
- 마지막 OVC 수신 시각은 종목별로 유지한다. 선택 종목만 stale 여부를 계산하지 않고 관심계약 카드마다 수신 상태를 표시할 수 있도록 데이터 모델을 확장한다.
- 1분봉과 로컬 10분봉은 선택 여부와 관계없이 OVC로 갱신한다. 화면은 선택된 종목만 다시 그리되, 비선택 종목의 데이터도 캐시와 DB에 계속 누적한다.
- 기간/종목 전환은 저장 데이터 읽기만 수행하며 새로운 과거 조회를 유발하지 않는다.

## 8. 구현 단계

1. **OVC 체결 버퍼와 집계기**: OVC callback에서 체결 이벤트를 snapshot coalesce 전에 전달하고, 종목별 10분 링 버퍼와 분봉 계산을 구현한다.
2. **분봉 저장/캐시 연결**: 생성된 1분봉을 기존 DB upsert 경로에 저장하고 메모리 캐시 및 차트 이벤트로 연결한다. 종료 시 열린 분봉을 flush한다.
3. **로컬 10분봉 합성**: 세션 기준 1분봉 그룹 집계와 그래프 반영을 추가한다. 기존 `ncnt=10` 역사 조회 의존을 제거한다.
4. **주기 보정 스케줄러**: 대시보드 차트 진입 시 발생하는 `o3103` 호출을 제거하고 10분 주기 관심계약별 `ncnt=1` 보정 작업을 공통 Xing 스케줄러에 넣는다.
5. **생명주기와 상태**: 수신 시작/정지, 계약 변경, 화면 이탈, 연결 해제, 앱 종료 시 버퍼·타이머·대기 요청의 동작을 연결한다.
6. **검토**: 빌드, 집계 경계/시간 역전/거래량 규칙 점검, 시뮬레이션 OVC 입력, Xing 모의계정에서 실제 응답·공통 제한·DB 정합성을 확인한다.

## 9. 수용 기준

- 관심계약 전체가 선택 여부와 무관하게 OVC를 구독하고, 화면 비활성화나 수신 정지 시 해당 구독을 정리한다.
- OVC 체결 이벤트가 최신 스냅샷 저장용 coalesce에 의해 유실되지 않고 1분봉으로 집계된다.
- 1분봉 OHLC와 거래량이 테스트 이벤트의 시간순 체결가와 체결수량 합계에 일치한다. 같은 초 다중 체결, 지연 도착, 거래일 변경, 앱 재시작 경계를 포함한다.
- 10분봉은 로컬 1분봉만으로 생성되며 `ncnt=10` 요청을 보내지 않는다.
- 차트 종목 선택/재선택과 기간 전환으로 `o3103`가 추가 전송되지 않는다.
- 관심계약 전체에 대해 10분 보정 작업이 발생하며 모든 호출이 공통 1초/최근 600초 200건 한도를 지킨다. 대기/건너뜀/실패가 로그와 상태에서 확인된다.
- `o3103` 응답값은 중복 키 없이 DB에 병합되고, 실패한 서버 응답은 기존 로컬 봉을 지우지 않는다.
- OVC 이벤트 수신이 DB 쓰기 지연으로 멈추지 않고, 화면 선택 변경이나 화면 이탈 뒤 이전 종목 응답이 잘못된 차트를 덮지 않는다.

## 10. 결정 사항과 남은 확인

이 문서의 기본안은 원시 OVC를 최근 10분 동안 메모리에만 두고, 완성 분봉과 최신 스냅샷만 DB에 보존하는 것이다. 별도 원시 틱 저장과 장기 틱 백테스트는 범위 밖이다.

로컬 `OVC.res`에서 `trdq`가 체결량 필드로 정의되고 `trdtm`이 6자리 현지 체결시각임을 확인해 현재 집계를 구현했다. 다만 실제 Xing 모의계정에서 이벤트 빈도/`trdq`가 각 이벤트의 건별 수량인지, 거래일 경계·서머타임·세션 시작 시각이 맞는지는 아직 런타임 확인이 필요하다. 검증 결과와 다른 의미가 확인되면 집계 규칙을 조정한다.

## 11. 구현 현황

- OVC 수신 이벤트를 최신 스냅샷 coalesce 이전에 `OFutureMinuteBarAggregator`로 전달한다. 종목별 최근 10분 체결을 메모리에 두고 체결 거래일/현지시각으로 1분 OHLCV를 만든다.
- 저장된 1분봉 이력 전체에서 날짜·시각별 10분 OHLCV를 다시 구성하고, 현재 열린 10분 구간은 OVC로 바뀐 1분봉을 포함해 갱신한다. 10분봉은 원시 체결의 최신 값이 아니라 해당 구간에 속한 1분봉들의 시가·고가·저가·종가·거래량을 나타낸다. 음수 선물 가격은 허용하고 유한하지 않은 가격은 집계에서 제외한다.
- 생성된 두 주기의 봉은 기존 `OFutureMinuteBars` 키로 최대 1초 단위 upsert하고, 선택 종목 차트를 배치 갱신한다. 화면 선택 전환 시에는 DB에 저장된 봉을 불러온다.
- 과거 분봉 로드와 `o3103` 1분봉 저장 뒤에도 같은 1분봉→10분봉 집계를 수행한다. 10분 차트에는 저장된 이력과 진행 중인 최신 봉을 함께 표시하며, 1분봉이 없는 구간에 임의의 봉을 만들지 않는다.
- 차트 선택/기간 변경 때 `o3103`을 보내지 않는다. OVC 수신 활성 상태에서 시작 시 1회, 이후 10분마다 관심계약 종목별 최신 1분봉 요청을 공통 TR 스케줄러에 제출한다. 각 주기 요청은 페이지 수를 1로 제한하고 10분봉 재조회는 하지 않는다.
- 수신 정지/화면 이탈 시 타이머와 아직 대기 중인 보정 요청을 취소하고, 재진입 시 사용자 수신 의도에 따라 구독 및 보정을 다시 시작한다.
- Visual Studio 2022 MSBuild `Debug|x86` 빌드가 통과했다. 실제 Xing 입력, 장 세션 경계, 여러 계약 동시 수신, 공통 TR 큐의 실응답 검증은 남아 있다.

**주식·해외선물 합산 TR 제한은 그대로 유지한다.** OVC 실시간 구독량은 일반 TR 호출 제한과 별도지만, 관심계약 수가 많을 때 서버 보정은 200건/10분 예산을 상당 부분 차지할 수 있다. 따라서 `o3103` 보정 간격을 종목별 10분으로 보장하려면 활성 관심계약 수와 다른 일반 TR 사용량을 함께 고려해야 한다. 현재 예상 관심계약 수가 이 예산에 맞는지 구현/운영 단계에서 계측한다.
